# SEEDANCE-PIPELINE-v001

## 职责划分

### 导演助理

- 把完整剧情拆为镜头和约 5 秒生成单元。
- 一次性规划全片节奏、轴线、动作链、表情曲线和声音意图。
- 编译每镜 Prompt、输入素材、Seedance 参数和连续性依赖。
- 调度任务、归档任务 ID、下载结果并组织质检。
- 默认把声音方案编译为现场环境声、动作音效和必要对白；除非用户或剧情明确要求，禁止添加背景音乐。

### Seedance

- 根据文本、角色参考、关键帧、场景参考、动作参考和可选音频生成主体视频。
- 负责角色表演、空间运动、运镜、动作特效和镜头内动态。

### FFmpeg

- 负责无损或可控转码、硬切拼接、音轨合成、响度、片尾、交付封装和技术检查。

### HyperFrames

- 仅在明确需要可编辑字幕、数据界面、片头、Logo 动画或信息图时使用。
- 不再把漫画动作拆成浏览器 DOM 元素逐帧拼接。

## 生成单元

- 默认单元：`5s`。
- 可按模型能力使用更长片段，但高强度羽毛球动作仍优先拆为短单元。
- 一个 5 秒单元可包含多个明确硬切；复杂连续动作优先一个动作阶段一个单元。
- 每个单元必须有首帧意图、峰值动作、末帧去向和下一镜入口。

## 批次调度

- `depends_on: []`：可与其他无依赖镜头并行。
- `continuity_from: null`：不需要继承上一个视频尾帧。
- `continuity_from: SHOT-XXX`：等待前镜成功并获取尾帧，再把该尾帧作为当前镜首帧输入。
- 不因某一镜失败而重跑已通过镜头。
- 每个请求保存模型 ID、Prompt 哈希、素材 URI、参数、任务 ID、种子和输出文件。

## TOS 素材层

- 地域固定为 `cn-beijing`，Endpoint 为 `tos-cn-beijing.volces.com`。
- 存储桶保持 `private`，禁止为方便调用而改成公共读。
- 永久档案只记录桶名、对象键、文件哈希、大小和 ETag，不记录 AK、SK 或签名参数。
- Seedance 输入使用短期预签名 GET URL；当前默认有效期为 72 小时。
- 签名 URL 只允许写入每集 `runtime/`，该目录必须被 Git 忽略。
- 新设备或签名过期后，运行 `工具/seedance/tos_upload_refs.py`：已存在的对象按固定对象键
  校验/覆盖，并生成新的运行时链接。
- 当前 SDK 基线为火山引擎 TOS Python SDK `tos==2.9.2`。

## Prompt 编译顺序

1. 风格版本与画面语言。
2. 角色 ID、版本、服装和装备。
3. 场景与叙事目的。
4. 时间码动作。
5. 机位、焦段感、透视、消失点和三层空间。
6. 羽毛球生物力学或具体日常动作逻辑。
7. 特效、光色和声音要求。
8. 首尾帧与连续性。
9. 负面约束。

提示词中以“图片1”“视频1”“音频1”引用 `content` 数组中的素材，不直接暴露内部资产 ID。

## 全局声音策略

- 默认：`BGM: NONE`。
- 可使用：鞋底摩擦、脚步、呼吸、衣料、挥拍风切、击球、球网、观众远景和球馆空间混响等现场音效，以及剧情明确需要的对白。
- 禁止默认添加：背景音乐、歌曲、旋律铺底、节拍轨、预告片鼓点或音乐性转场。
- 只有用户或当前剧情文件明确批准时，才能把 BGM 写入 Prompt 或后期音轨；批准必须记录具体镜头、音乐用途和起止时间。
- 若模型输出擅自带入背景音乐，标记为声音连续性失败；优先分离/移除音乐，无法干净修复时再请求用户授权重生成。

## 质检

### 自动技术检查

- 文件存在且可解码。
- 时长、分辨率、帧率和音轨符合批次定义。
- 无黑帧、空帧、长时间冻结、规律频闪和异常尾帧。
- 预期硬切点附近不存在时间轴空洞。
- 默认无背景音乐；只存在批次允许的现场音效、环境声和对白。

### 视觉检查

- 锁定角色、毛纹、耳尾、服装和装备不漂移。
- 手指、肢体、球拍、球和球网无穿模或增殖。
- 重心、步法、肩胯、触球点、拍面和球路正确。
- 镜头轴线、屏幕方向、光线和色彩连续。
- 喜剧峰值具有进入、峰值和回弹。

### 返工

- 只重做失败单元。
- 记录具体漂移变量，不使用“感觉不像”作为返工指令。
- 同类失败累计两次时，先修改关键帧或动作参考，不继续盲目抽卡。

## 审批闸门

以下动作必须在当前对话中获得用户明确确认：

- 上传本地素材。
- 创建 Seedance 任务。
- 查询或批量轮询付费账户任务。
- 下载带有效期的生成结果。
- 重新生成失败镜头。

离线规划、Prompt 编译、JSON 验证、文件检查和成本占位估算不需要额外确认。

## 凭证与设备边界

- 只允许从环境变量读取：方舟使用 `ARK_API_KEY`，TOS 使用 `TOS_ACCESS_KEY` 和
  `TOS_SECRET_KEY`。
- 凭证不得写入 Markdown、JSON、Prompt、命令参数、日志、Git 或聊天消息。
- 凭证是设备本地状态，不随仓库迁移；新设备必须重新配置。
- Windows 中 Codex 沙箱账户可能看不到真实用户的环境变量。执行联网工具时，应在真实用户
  进程中从 User 环境加载变量，但不得打印变量值。
- IAM 初始接入可临时使用 `TOSFullAccess`；桶创建完成后应改为仅允许目标桶及目标前缀的
  最小权限策略。
